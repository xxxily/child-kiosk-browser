## Child Kiosk Browser v0.3.7

本版本针对“后台测试高德定位正常，但网页触发定位仍偶发 `INVALID_USER_KEY`”继续修复。根据诊断日志，主进程和 `:webview` 进程使用的是同一个高德 Key 指纹，包名/SHA1 也一致，因此本轮把网页定位的高德调用从 WebView 独立进程收回主进程执行，复用后台测试已经验证正常的 SDK 初始化路径。

### 本轮核心变化

* **网页定位走主进程代理**：网页 `navigator.geolocation.getCurrentPosition` 和 `watchPosition` 通过主进程定位代理执行，不再直接在 `site.anzz.childkiosk:webview` 进程初始化高德 SDK。
* **规避 WebView 进程鉴权异常**：主进程代理复用后台测试路径，降低高德 SDK 在 WebView 独立进程内出现 `INVALID_USER_KEY` 的风险。
* **初始化顺序收紧**：去掉应用启动和 Key 输入时提前调用 `setApiKey` 的行为，只在定位请求开始前按“隐私确认接口 -> setApiKey -> 创建 `AMapLocationClient`”执行。
* **诊断更容易确认路径**：网页定位结果说明会附带“主进程定位代理”，用于确认网页请求已经走新代理路径。
* **仍保留系统回退**：高德失败时继续按现有 provider 策略回退系统定位，网页不会因为高德异常直接崩溃。

### 建议验证

1. 安装 `child-kiosk-browser-0.3.7-enhanced-release.apk`。
2. 完全退出并重新打开应用，进入可信网页触发 `navigator.geolocation`。
3. 打开后台“能力增强”里的定位诊断详情，确认网页定位记录的说明中出现“主进程定位代理”。
4. 确认网页定位记录不再持续出现 `site.anzz.childkiosk:webview` 进程下的高德 `INVALID_USER_KEY`。

## Child Kiosk Browser v0.3.6

本版本继续排查网页触发高德定位时仍可能出现 `INVALID_USER_KEY` 的问题。核心变化是修复高德配置写入跨进程 runtime 快照时的异步竞态，并新增脱敏诊断上下文，用来直接对比后台测试路径和 `:webview` 网页路径实际使用的高德 Key 指纹与配置来源。

### 本轮核心变化

* **不泄露敏感信息**：诊断只记录 Key 长度和短指纹，不记录高德 Key 原文，也不记录定位坐标。

本版本为儿童浏览器带来了全新的**多标签页 (Multi-tab) 管理机制**以及针对内存性能的**后台不活跃标签挂起/冻结 (LRU Suspension)**优化：支持在悬浮控制面板中进行标签卡片预览、切换、一键关闭与新建 (`+`)；网页跳转新窗体自动作为新 Tab 在浏览器中独立打开；采用 LRU 缓存策略挂起多余后台 WebView 释放 Native 物理内存，切回时还原历史数据，极致优化内存和稳定性。

> **说明**：本 APK 使用 debug 签名，仅供调试与家庭内部部署。生产/商用请自行用正式 keystore 重新签名。

### 本版本核心变化

* **多标签管理交互**：
  - 点击悬浮球并展开面板，可以看到“标签页 (N)”列表。
  - 点击列表右上角加号可新建空白标签页。
  - 水平滑动的标签卡片展示 Title/URL，右侧带独立的 `x` 销毁关闭按钮，当前活动标签呈高亮。
* ** window.open 规范对齐**：
  - 重写了 `onCreateWindow`，网页端触发的新窗体弹出将不再使用重叠子窗口，而是自动在浏览器中开辟出一个新的独立 Tab 标签卡片，完全与现代主流浏览器能力看齐。
* **后台标签 LRU 挂起冻结**：
  - 限制最多保留 2 个未冻结的 WebView。超标时，按照最久未使用原则对后台 Tab 自动执行 `saveState()` 保存，随后 `destroy()` 彻底回收它的 DOM 树 and 物理渲染内存。
  - 重新点击切换至被冻结的 Tab 时，创建新实例并执行 `restoreState()` 极速唤醒并复原，避免多标签同开时的 OOM 奔溃风险。

## Child Kiosk Browser v0.2.9

本版本重点修复并重构了网页过滤与儿童模式下，因 WebView 跨线程调用实例方法引发的必发性闪退问题；同时全面解决了用户输入网址时输入法会遮挡悬浮地址输入框的 UI 交互硬伤，极大地改善了横屏和竖屏模式下的可用性。

### 本版本核心变化

* **多线程调用 getUrl() 闪退修复**：
  - **原因**：此前在资源拦截的 `shouldInterceptRequest`（执行在 WebView 的后台网络加载线程）中，直接跨线程物理调用了线程不安全的 `view?.url` 获取页面顶层链接，导致 WebView 在线程校验时抛出异常奔溃并直接杀掉进程。

* **地址栏软键盘遮挡自适应避让**：
  - **动态 IME 高度自适应**：动态监听 WindowInsets IME 键盘高度变化，并在软键盘弹起时，自动在 Y 轴将悬浮地址面板限制在键盘顶边缘上方（留出 16dp 安全边距）。
  - **横屏压扁高度压缩算法**：针对横屏等极度矮小的屏幕场景，当键盘弹起时自动把面板的后退/强刷等 sections 滚动容器的高度压缩压扁，使其在软键盘上方窄小屏幕中完全露出。
  - **软键盘属性同步**：在 `AndroidManifest.xml` 中将 `MainActivity` 和 `WebViewActivity` 的 softInputMode 显式标记为 `adjustResize` 配合系统 resize。

## Child Kiosk Browser v0.2.8

本版本彻底修复了开启网页过滤（轻量过滤/标准儿童过滤）时在广告资源拦截的瞬间直接闪退的根本性缺陷。方案通过将拦截状态码规范为 `200 OK` 规避了 Chromium 底层的网络协议崩溃，同时采用跨进程本地广播隔离解耦了 `:webview` 进程的磁盘 IO 锁竞争，并为 WebViewClient 引入了 `onRenderProcessGone` 渲染异常退出防护，极大地保障了 Kiosk 系统的强健性。

> **说明**：本 APK 使用 debug 签名，仅供调试与家庭内部部署。生产/商用请自行用正式 keystore 重新签名。

### 本版本核心变化

* **广告拦截网络协议栈合规优化**：
  - 将所有拦截资源的响应从违背 RFC 规范的带实体 `204 No Content` 更改为安全的 `200 OK`。
  - 对于图片（`IMAGE`）资源被拦截时，返回 1x1 透明 GIF 占位字节流，其他资源返回空字节流。此优化彻底清除了 Chromium 内核因检测到 204 状态码附带 InputStream 而触发 Native 断言失败或段错误直接导致进程退出崩溃的死穴。
* **跨进程日志记录架构隔离**：
  - 移除了隔离进程 `:webview` 中对共享文件 `filter_events.json` 的直接读写，避免引发多进程无锁状态下的文件损坏和内核 IO 权限被系统查杀问题。
  - 改在 `:webview` 拦截到广告时向主进程发送限制包名的自定义本地广播。主进程由新设的 `FilterEventReceiver` 顺次无冲突地将过滤事件写入磁盘，杜绝了并发读写冲突和任务积压引发的 OOM。
* **渲染进程异常挂掉防闪退防护**：
  - 重写了 `onRenderProcessGone`，在 WebView 所在的 `:webview` 渲染进程被系统由于内存限制强制杀死或因其他意外崩溃挂掉时，捕获异常并安全注销并移除该 WebView，弹窗提示家长尝试恢复，向 Android 系统告知宿主应用已妥善控制，不再发生应用直接闪退的事故。

   - 打开各种包含跟踪代码、广告资源的白名单网页，确认页面均能流畅加载、正常排版。被拦截的广告处展现为空或 1x1 透明图，不再发生任何闪退。

> **说明**：本 APK 使用 debug 签名，仅供调试与家庭内部部署。生产/商用请自行用正式 keystore 重新签名。

### 本版本核心变化

* **悬浮球视觉与动效双重优化**：
  - 视觉球直径从 `72dp` 精简为 `52dp`，但通过 InsetDrawable 维持 `72dp` 宽大的无障碍物理触控热区。
  - 采用全新的青绿渐变背景与半透明发光白色边框，提升立体质感。
  - 新增边缘半隐藏 Alpha 渐变逻辑（空闲 2.8 秒后自动淡出至 `0.4f`，拖拽和交互时立即恢复为不透明 `1.0f`）。
* **手机桌面 APP 风格重构**：
  - 剥离白名单应用原本的硬白底卡片和阴影框架，呈现纯粹的桌面应用图标质感。
  - 针对默认预置 App，根据应用 ID 自动应用 5 种精美莫兰迪色系渐变底色，搭配白色图标和描边边框。
  - 应用图标框的尺寸在小、中、大三种模式下进行了更合理的比例计算。
* **10 款首屏壁纸与自适应配色**：
  - “界面与显示配置”二级子页面新增了“首屏壁纸与配色配置”色块滑动选择组件。
  - 支持 10 种高级预设壁纸（包含温暖明黄、莫兰迪蓝、森林绿意、薰衣草紫、极简纯黑等）。
  - 主屏标题、标签页以及应用前景色，都会根据壁纸的明暗属性（isDark）自动完成亮/暗色系无缝自适应切换。
* **快速模式配置二级菜单化**：
  - 配置主页面去除了直接铺开的快速模式卡片，以全新设计的“快速切换模式”列表项置顶显示，并能展示当前所处模式的小字。
  - 点击“快速切换模式”进入二级配置菜单执行模式切换，后台界面更加整洁统一。

### 建议验证

重点测试：

1. **壁纸与APP图标风格**：
   - 进入“配置后台 -> 界面与显示配置 -> 首屏壁纸与配色配置”，尝试切换为“极简纯黑”或“莫兰迪蓝”，返回主界面确认壁纸成功更换。
   - 确认主界面的白名单 App 显示不再带有原有的白色方块，图标尺寸和文字排版优雅整齐。
   - 确认文字和顶部锁屏按钮在暗色壁纸下为白色，在亮色壁纸下为深色。
   - 切换分类标签，确认在暗黑模式下标签呈现半透明的毛玻璃质感。
2. **快速模式二级菜单**：
   - 确认配置首页第一个卡片顶部为“快速切换模式”，其下方显示“当前：正常模式”（或其他模式）。
   - 点击该列表项，确认能顺利进入二级页面，切换模式（如儿童模式）后返回，确认状态刷新，且再次点击管理按钮时触发认证。
3. **网页悬浮球交互**：
   - 任意打开一个网页，确认悬浮球大小更加精巧，拖动到边缘并等待 2.8 秒，确认悬浮球贴边且透明度淡出至 0.4f。
   - 触摸悬浮球，确认透明度立刻恢复为 1.0f 并不透明显示。

## Child Kiosk Browser v0.1.1

本版本重点增强“网页广告与弹窗过滤”能力，让应用接入主流 Adblock 规则生态，而不是维护一套孤立的私有规则。管理员可以使用内置订阅目录、自定义 HTTPS 订阅和自定义 Adblock 规则来增强儿童浏览场景下的抗干扰、去污染能力，同时通过站点例外和过滤事件排查降低误伤风险。

> **说明**：本 APK 使用 debug 签名，仅供调试与家庭内部部署。生产/商用请自行用正式 keystore 重新签名。

### 本版本核心变化

* **兼容主流 Adblock 规则生态**：
  - 支持 ABP/EasyList、uBlock Origin 静态规则和 AdGuard 常用过滤语法子集。
  - 支持网络规则、例外规则、资源类型、三方/一方、站点域名限制、`badfilter` 和 `removeparam` 等高频能力。
  - 内置 EasyList、EasyPrivacy、AdGuard Chinese、AdGuard Mobile Ads、EasyList China、AdGuard Annoyances 等订阅目录。
* **自定义规则与订阅管理**：
  - 配置后台新增网页过滤总控、过滤强度、订阅开关、自定义 HTTPS 订阅和自定义规则输入。
  - 规则构建报告会展示总规则、已启用规则、网络规则、元素隐藏、scriptlet 和不支持语法数量。
  - 支持站点级关闭网络过滤、元素隐藏、scriptlet 或临时放行，用于处理误伤。
* **更强的页面去干扰能力**：
  - 支持元素隐藏规则，将匹配 CSS 注入当前页面以隐藏广告位、赞助块和部分干扰组件。
  - 支持安全 allowlist scriptlet，不执行订阅里的任意 JavaScript。
  - 支持弹窗过滤和主框架导航追踪参数清理，减少广告跳转窗口和污染参数。
* **性能与稳定性复核**：
  - WebView 请求拦截路径只读取已预热过滤引擎缓存，不在 `shouldInterceptRequest` 中编译规则或读取订阅文件。
  - 过滤事件改为后台串行写入，避免拦截线程同步读写磁盘。
  - WebView 独立进程继续通过启动 Intent 接收过滤配置快照，预加载池也会按运行时配置区分实例，避免旧设置污染新页面。

### 建议验证

重点测试：

1. 进入配置后台，开启“网页过滤总控”，确认规则统计能显示内置订阅和自定义规则的解析结果。
2. 打开常见广告测试页或带广告资源的网站，确认图片、脚本、统计请求会被过滤事件记录。
3. 添加一条自定义规则，例如 `||example.com/ad.js^`，新打开网站后确认规则生效。
4. 添加站点例外，分别关闭网络过滤、元素隐藏和 scriptlet，确认新打开网站按例外配置执行。
5. 测试中文站点、教育站点、小游戏和视频播放，确认过滤不会破坏核心内容；如有误伤，可通过最近过滤事件定位规则来源。
6. 开启网页预加载后切换过滤设置，确认新打开的网站按最新过滤快照执行。

## Child Kiosk Browser v0.1.0

本版本新增“快速模式”与“网页悬浮球操作入口”。默认正常模式更接近普通浏览器：无需认证即可单击打开管理菜单，打开网页后可通过悬浮球输入网址、查看当前 URL、后退、前进、刷新或停止加载。管理员仍可切换到儿童模式启用更严格的锁定、认证和 WebView/系统限制，也可进入自定义模式逐项调整。

> **说明**：本 APK 使用 debug 签名，仅供调试与家庭内部部署。生产/商用请自行用正式 keystore 重新签名。

### 本版本核心变化

* **快速模式预设**：
  - 配置后台新增“正常模式 / 儿童模式 / 调试模式 / 自定义模式”。
  - 正常模式为默认模式，默认关闭认证、软锁和网页/系统限制，右上角管理入口单击即可打开。
  - 儿童模式默认开启认证、软锁、隐藏管理入口和限制项。
  - 调试模式默认放开限制，并开启 Chrome Inspect 与网页内置调试面板。
  - 屏幕方向、图标大小、主页标题、白名单、缓存/预加载等非限制选项不会被模式切换重置。
* **网页悬浮球操作入口**：
  - 新增可拖拽、边缘吸附、空闲半隐藏的原生悬浮球。
  - 悬浮球面板支持 URL 输入访问、当前 URL 查看、后退、前进、刷新和停止加载。
  - 正常模式默认开启悬浮球；配置后台新增“网页悬浮球操作入口”开关，可在自定义模式下控制其它模式是否显示。
* **显式配置项补齐**：
  - “单击管理入口直接打开菜单”“禁用语音助手入口”“禁止安装未知来源应用”“网页悬浮球操作入口”等能力都已变成可见配置项，避免隐性规则。
  - WebView 独立进程通过启动 Intent 接收悬浮球配置快照，保持设置来源明确。

### 建议验证

重点测试：

1. 新安装或清空数据后进入配置后台，确认当前为正常模式，右上角管理入口单击可打开菜单。
2. 正常模式打开网站，确认悬浮球显示、可拖拽、可展开面板、可半隐藏。
3. 在悬浮球中输入 `example.com`，确认补全为 `https://example.com` 并加载。
4. 在同一网页内测试后退、前进、刷新和加载中停止按钮。
5. 切换儿童模式后新打开网站，确认悬浮球默认不显示；再手动开启“网页悬浮球操作入口”，确认新打开网站生效且模式显示为自定义。
6. 切换模式时确认屏幕方向、图标大小、主页标题和白名单没有被重置。

## Child Kiosk Browser v0.0.5

本版本重点解决了 WebView 网页浏览时的**白屏、冷启动耗时、SPA 单页应用过渡闪烁**等体验问题。引入了**网页后台预加载与复用池**、**系统空闲时的 WebView 引擎预热**、**7天自动缓存自动回收与一键清理**，并重新设计了**全屏加载遮罩、平滑过渡动画和友好的网页错误拦截页**。为儿童上网和网页游戏提供无缝、流畅、“秒开”的视觉体验。

> **说明**：本 APK 使用 debug 签名，仅供调试与家庭内部部署。生产/商用请自行用正式 keystore 重新签名。

### 本版本核心变化

* **后台预加载与秒开复用池 (Phase 4)**：
  * 家长可在控制台开启「网页后台预加载」选项（默认开启）。
  * 开启后，主页在完全闲置（通过主线程空闲 `IdleHandler` 触发）时，会自动在后台通过协程分步预加载排名前 3 的常用站点。
  * 当儿童点击卡片时，直接从预加载池中取出已缓存/已渲染完毕的 WebView 挂载使用，实现瞬间打开的秒开体验。
  * **OOM 与内存防线**：集成了 Application 的 `onTrimMemory` 监听，在系统内存低/极低时自动裁减或清空预加载池以保障系统整体稳定。
* **自定义进程架构简化**：
  * 移除了 `WebViewActivity` 的独立 `:webview` 子进程。由于 Android 系统限制，非同进程的 View 实例无法直接跨进程共享或 addView 挂载，为了实现 WebView 后台预加载的跨 UI 挂载，重构并合并回了主进程。
* **Chromium 引擎冷启动预热 (Phase 2)**：
  * 在 Application 初始化时自动在主线程空闲期预创建一个轻量 WebView 实例，触发 Chromium 引擎的初始化，彻底消除了用户首次打开应用网页时引擎冷启动的数百毫秒耗时。
* **暖色底色与白屏消除**：
  * 将 `WebViewActivity` 的 Activity 窗口背景、Compose 布局底色、以及 `WebView` 实例初始画布底色统一设置为应用暖黄色 `#FFF8E1`，网页完全载入后再自动恢复白色，完美消除了白屏闪烁，并避免了无背景网页文字无法识别的问题。
* **全屏网页加载遮罩层与三重就绪判定 (Phase 1)**：
  * 在网页加载未就绪时显示全屏加载遮罩，展示专属图标（自动解析网络 favicon 或矢量图）、圆形进度条和儿童友好提示文案。
  * **三重就绪判定**：结合网页进度 >= 85%、`onPageFinished` 触发以及 `evaluateJavascript` 注入 JS 检查 DOM 实质子节点渲染状态，完美解决了传统方案中 SPA 单页应用因为“空壳 HTML”瞬间关闭遮罩暴露白屏的痛点。
  * **最少展示时间限制**：预载遮罩最少展示 600ms，配合 400ms 的淡出过渡动画，提供精致平稳的过渡效果。
* **友好网页错误与异常拦截提示**：
  * 当网页加载遇到主框架加载失败、超时、SSL证书异常或服务器返回 HTTP 4xx/5xx 时，加载遮罩会平滑切为精美的报错提示页，并提供「重试一下」与「返回乐园」按钮，代替原始丑陋的系统崩溃白屏或无反应卡死。
* **双重缓存策略与定时垃圾清理 (Phase 3)**：
  * 尊重 HTTP 头缓存，且启动时会自动检查距离上次清理是否超过 7 天，是则自动在后台进行缓存清理。
  * 家长管理后台新增「立即清理」卡片，一键清除网页缓存与 Cookie，省心好用。

## Child Kiosk Browser v0.0.4

本版本支持**删除预设白名单应用**、**内置图标库扩增（12个）**、**自定义 Favicon 卡片排版美化与实时预览**，并新增了**退出网站验证开关**、**主页右上角家长控制锁头图标显示/隐藏选项**以及**主页标题文本自定义与隐藏选项**，进一步提升了家长控制的自由度与用户界面的美观性。

> **说明**：本 APK 使用 debug 签名，仅供调试与家庭内部部署。生产/商用请自行用正式 keystore 重新签名。

### 本版本核心变化

* **白名单应用完全自由删除**：
  * 去除了默认预设应用（如腾讯视频、爱奇艺等）的删除限制，家长在后台控制台可自由删除任意默认白名单应用，彻底避免了应用“锁死”无法清理的问题。
* **内置图标库扩增**：
  * 内置图标从 5 个扩增至 12 个，包含：星星、书本、手柄、视频、音乐、地球、相机、学校、灯泡、笑脸、心形、主页，为不同类别的网站应用提供更丰富的视觉选项。
* **自定义 Favicon 卡片排版优化与实时预览**：
  * 重构了自定义图标输入卡片的布局，由横向单行重构为纵向两行设计。
  * 引入了 56dp x 56dp 的 Coil `AsyncImage` 框进行实时图片预览。当输入有效的 HTTP/HTTPS 图片网址时，自动加载展示预览，加载失败或格式不合法时优雅显示警告，界面高档雅致。
* **网站退出验证按需配置（默认无需验证）**：
  * 新增“退出网站时需要验证”开关（默认关闭）。
  * 关闭时，按返回键或在顶部盲区连续点击 5 次可直接退回主页，极大地简化了用户的常规使用；开启后则与以往一致，需通过家长密码验证才能退出，满足了安全退出的个性化需求。
* **可交互管理锁图标与隐藏配置**：
  * 默认在主页面右上角提供一个精致的“锁头”图标引导首次使用的用户，点击该锁头多次即可直接弹出验证框，降低了家长后台的认知与寻找门槛。
  * 在后台控制台提供“隐藏右上角管理锁图标”开关，开启隐藏后，锁头图标不显示，依然保留通过在右上角无图盲点击 5 次触发密码验证的隐藏机制。
* **主页标题文字自定义与隐藏**：
  * 提供了自定义主页标题文本配置，可将默认的“我的游戏乐园”修改为任意个性化名称。
  * 提供了“隐藏主页标题文字”开关，允许隐藏该文本，留出更多屏幕空间给应用网格。

## Child Kiosk Browser v0.0.3

引入**自定义网址图标与 Favicon 自动推导**，支持**屏幕显示方向设置**以及**首屏网格图标大小缩放**，并完美解决横屏下 Dialog 遮挡与状态栏灰色半透明块卡死的体验瑕疵。

> **说明**：本 APK 使用 debug 签名，仅供调试与家庭内部部署。生产/商用请自行用正式 keystore 重新签名。

### 本版本核心变化

* **网络自定义图标与 Favicon 自动推导**：
  * 引入 `Coil` 异步图片加载库，支持网络图标缓存与优雅的加载失败（显示 Star 图标）容错。
  * 添加应用时自动根据输入的 URL 提取协议、主机及端口，并自动拼接推导为默认的 `/favicon.ico` 地址。
  * 提供内置图标与自定义 URL 输入框的勾选单选卡片，可任意选择及修改，默认优先填充推导的 Favicon。
* **屏幕显示方向配置**：
  * 支持三种显示方向：自适应（AUTO）、锁定横屏（LANDSCAPE）、锁定竖屏（PORTRAIT）。
  * 移去了 Manifest 中的硬编码方向锁，在 `onCreate` 最早期以 Preference 同步设置，完美解决了 Activity 启动瞬间闪屏和多进程 WebView 的方向一致性。
* **首屏图标显示大小**：
  * 支持三种图标显示大小：小（SMALL，网格 `90.dp`）、中（MEDIUM，网格 `120.dp`）、大（LARGE，网格 `160.dp`）。
  * 适合横屏模式下排布更多的应用，极佳地适应不同设备屏幕比例。
* **系统栏自动重置沉浸**：
  * 引入系统 insets 监听器，在儿童下拉呼出状态栏（出现半透明灰条）后，**自动在 3 秒后重新收回隐藏系统栏**，彻底杜绝状态栏在部分 OEM 设备上卡死占位。
* **局域网与测试 HTTP 放行**：
  * 网络配置文件与 Android 清单全面放行明文 HTTP 协议流量，并为家长添加 HTTP 应用时增加醒目的橙色风险告知。
* **Dialog 横屏滚动支持**：
  * 添加应用 Dialog 加入了滚动条（Column `verticalScroll`），解决了横屏下按钮被阻挡且无法交互的重大体验瑕疵。

## Child Kiosk Browser v0.0.2

引入**分级防护模型**：不再强制恢复出厂 + Device Owner。普通侧载安装即可开箱使用，应用按当前可用权限自动选择最高防护等级。

> **说明**：本 APK 使用 debug 签名，仅供调试与家庭内部部署。生产/商用请自行用正式 keystore 重新签名。

### 本版本核心变化

| 档位 | 防护等级 | 激活条件 | 适用场景 |
| :--- | :--- | :--- | :--- |
| **Tier 1** | 企业级完全锁定（Device Owner） | 恢复出厂 + ADB 激活 | 长期专用平板，绝对防逃逸 |
| **Tier 2** | 屏幕固定软锁（**默认**） | 普通安装即可 | 家长普通侧载，日常防误触 + 基础防逃逸 |
| **Tier 3** | 无系统级锁定 | 普通安装 + 后台切换 | 开发调试、临时体验、配置网站 |

- 主网格**不再以 Device Owner 为使用前提**：装上即可用，无需 ADB；
- 家长后台新增「**防护等级**」卡片，可在 Tier 2 / Tier 3 间切换，并内置 Device Owner 升级引导；
- 沙箱安全能力（HTTPS 强制、同源白名单、广告/下载拦截、SSL 严格校验、独立进程）、家长验证、时长限制**三档完全一致**，分级只影响系统级锁定强度。

### 安装与部署

#### 路径 A：普通侧载（推荐给大多数家长 / 开发者）

无需恢复出厂、无需 ADB：

1. 下载下方 Assets 中的 `child-kiosk-browser-0.0.2-release.apk`；
2. 直接安装并打开，默认进入 **Tier 2 屏幕固定软锁**，主网格立即可用；
3. （可选）家长后台 → 防护等级卡片 →「设为默认主屏幕」，重启后自动回到本应用；
4. （可选）家长后台添加网站白名单、设置时长与 PIN 码。

> 想纯净体验或调试？家长后台把防护等级切到 **Tier 3** 即可随时用 Home 键进出。

#### 路径 B：Device Owner 完全锁定（要求绝对防逃逸时）

1. 平板**恢复出厂设置**，跳过 WiFi 与账号绑定；
2. 开启开发者选项与 USB 调试；
3. `adb install child-kiosk-browser-0.0.2-release.apk`；
4. 激活 Device Owner：
   ```bash
   adb shell dpm set-device-owner site.anzz.childkiosk/.MyDeviceAdminReceiver
   ```
   返回 `Active admin set` 即成功；
5. 家长后台防护等级卡片 →「设为默认主屏幕」选择本应用；
6. 重启平板，开机自动进入 Tier 1 完全锁定的儿童沙箱。

### 家长操作手册

- **进入家长后台**：屏幕**右上角** 80dp 区域 2 秒内连续点击 5 次 → 通过验证 → "进入系统白名单及时间配置后台"
- **切换防护等级**：管理后台顶部「防护等级」卡片
- **退出锁定**：管理后台底部 "退出并安全解锁（返回系统桌面）"
- **修改密码 / 切换验证方式**：管理后台 → 家长身份验证配置
- **设置时长**：管理后台 → 儿童健康使用时长限制（拖动 Slider）
- **添加新网站**：管理后台 → 右下角 + 按钮（仅支持 https，自动连通性检测）

### 已知限制

- APK 使用 debug 签名，仅适用于个人测试 / 家庭部署
- Tier 2 屏幕固定可被系统手势（长按 返回+最近任务）解除，防护强度低于 Tier 1，这是 Android 普通应用的固有限制
- Tier 2 首次激活时部分 OEM 会弹一次系统「是否固定此应用」确认框，属预期行为
- Tier 1 的 Device Owner 一旦激活无法通过卸载解除，必须 `adb shell dpm remove-active-admin` 或恢复出厂设置
- 部分国产 ROM 对 Device Owner 兼容性不一致，建议使用接近原生 Android 的设备（Pixel、AOSP 平板、Lenovo M 系列等）
