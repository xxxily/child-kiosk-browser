# 悬浮球操作入口与浏览器控制组件需求文档

## 背景

应用的真实网页当前由 `WebViewActivity -> FrameLayout -> WebView` 承载，并保持全屏显示。正常浏览模式需要具备 URL 输入访问、刷新、前进、后退等基础浏览器能力，但不希望引入传统浏览器顶部地址栏或顶部菜单，避免长期占用网页可视区域。

本需求将这些能力收敛到一个可拖拽、可边缘吸附、可自动半隐藏的悬浮球组件中。浏览器控制只是第一类内置能力，后续收藏、历史、阅读模式、页面工具、安全提示、家长操作等更多功能也会通过悬浮球作为统一入口集成。

## 开源集成评估

优先评估 Android 开源悬浮菜单、悬浮窗、FAB 菜单类库，但本项目不建议直接引入：

- 系统悬浮球库，例如 `dofire/Floating-Bubble-View`，通常围绕 `WindowManager`、Service、通知或系统 overlay 设计。它们适合跨应用浮窗，但本项目只需要 `WebViewActivity` 内的进程内覆层。引入系统 overlay 会增加权限、通知、生命周期和 kiosk 安全边界成本。
- 系统工具型项目，例如 `QuickBall`，能力完整但面向独立辅助球 App，通常需要无障碍、设备管理或系统设置权限，且 license 和功能边界都不适合作为本项目内嵌组件。
- FAB/圆形菜单库，例如 `Clans/FloatingActionButton`、`CircularFloatingActionMenu`、`FloatingToolbar`，主要解决按钮展开动画，不覆盖边缘吸附、半隐藏、URL 输入面板、WebView 状态同步、横竖屏安全约束和未来分组能力扩展。
- 较老库可能依赖旧 Support Library、JCenter/JitPack 或长期无人维护，引入后维护成本高于本项目自实现。

结论：继续自研进程内原生 View 覆层组件，不新增 Android 权限，不新增三方依赖，不改变 WebView 承载路径。组件定位不是系统悬浮窗，而是 `FrameLayout` 内可复用的悬浮操作入口。

## 设计目标

- 悬浮球壳层负责拖拽、边缘吸附、半隐藏、展开定位、屏幕尺寸变化约束。
- 操作面板负责展示可扩展功能分组，不把浏览器按钮硬编码成唯一能力。
- 浏览器控制作为默认分组实现 URL 输入、主页、收藏、历史、后退、前进、刷新和停止加载。
- 后续新增功能应通过 action/section 数据模型接入，而不是复制一套悬浮 UI。
- 组件不直接持有 WebView，不直接读取跨进程配置，不直接执行安全敏感策略。
- 组件能独立添加到 `FrameLayout` 根布局，位于 WebView 上层；真实网页仍由原生 WebView 全屏承载。

## 范围

本阶段实现：

- 原生 Android View 悬浮球操作入口组件。
- 悬浮球拖拽、边缘吸附、空闲半隐藏。
- 点击悬浮球展开操作面板。
- 面板支持功能分组与动作项渲染。
- 面板内提供 URL 输入、访问、后退、前进、刷新/停止加载、收起。
- 对外暴露浏览器状态与操作回调，供后续正常模式接入。
- 对外暴露通用动作模型，供后续收藏、历史、页面工具等能力接入。

本阶段不实现：

- 正常模式开关和入口接线。
- WebView 控制回调实际接入。
- 地址栏历史建议、搜索引擎、收藏夹、白名单策略编辑。
- 系统级悬浮窗或跨应用悬浮。
- 动作权限判定和家长认证流程本身；这些由宿主在回调中处理。

## 用户故事

- 作为儿童或家长，我希望网页保持全屏浏览，不被常驻顶部地址栏压缩。
- 作为家长，我希望需要输入 URL 时才打开控制面板，用完可以收起。
- 作为普通模式用户，我希望悬浮球能拖到顺手位置，并在不用时贴边半隐藏。
- 作为维护者，我希望组件能通过简单回调接入当前 WebView，不影响 kiosk 主屏和后台管理。
- 作为后续功能开发者，我希望新增操作时只需要声明一个分组和动作项，不需要重写拖拽、吸附、半隐藏逻辑。

## 功能需求

### 悬浮球

- 默认显示在屏幕右侧中部偏下位置。
- 支持手指拖拽。
- 松手后自动吸附到左边或右边。
- 空闲一段时间后，若面板未展开，悬浮球半隐藏到吸附边缘，仅保留可点击把手。
- 点击半隐藏把手时恢复并展开面板。
- 横竖屏切换后重新约束在安全可见区域内。

### 操作面板

- 点击悬浮球展开，再次点击或点关闭按钮收起。
- 面板靠近悬浮球显示，并根据左右边缘自动选择对齐方向。
- 面板宽度必须适配窄屏手机、横屏短高设备和平板。
- 面板不得要求顶部或底部固定工具栏。
- 面板顶部显示当前主分组标题或页面标题。
- 面板头部固定显示收起按钮，不随功能分组滚动。
- 面板支持多个功能分组。分组内容可包含输入区、动作按钮行、说明状态文本。
- 浏览器分组内容包含：
  - 当前 URL 输入框。
  - 访问按钮。
  - 后退按钮。
  - 前进按钮。
  - 浏览历史按钮；通过宿主回调打开可复用历史页面，不由悬浮组件直接访问数据库。
  - 刷新按钮；页面加载中时同一按钮可切换为停止加载。
  - 收起按钮。
- 当前 WebView 不可后退或前进时，对应按钮禁用。
- 页面 URL 变化且输入框未被用户编辑时，同步更新输入框。

### 功能分组和动作项

- 每个功能分组包含稳定 `id`、标题和动作列表。
- 每个动作包含稳定 `id`、标题、图标、是否启用、是否高亮、点击回调。
- 面板横向空间不足时，动作按钮必须保持 56dp 左右触控区域，并允许分组内部横向滚动。
- 禁用动作保留位置但降低透明度，避免按钮频繁增删造成布局跳动。
- 浏览器默认动作：
  - `browser.home`
  - `browser.bookmark`
  - `browser.history`
  - `browser.back`
  - `browser.forward`
  - `browser.refresh` / loading 时语义为 stop
- 面板固定动作：
  - `panel.close`
- 未来建议动作分组：
  - `navigation`：主页、新标签、历史、收藏。
  - `page_tools`：页面内查找、字体缩放、阅读模式、桌面模式。
  - `safety`：举报/拦截说明、临时放行、家长确认。
  - `session`：计时、休息、退出网页。

### URL 输入

- 输入 `https://example.com` 或 `http://example.com` 时原样访问。
- 输入 `example.com` 时默认补全为 `https://example.com`。
- 空输入不触发访问。
- 访问动作通过回调交给宿主 Activity，组件自身不绕过 WebView 的安全策略。

### WebView 状态

组件接收宿主传入的状态：

- 当前 URL。
- 页面标题。
- 是否可后退。
- 是否可前进。
- 是否加载中。
- 加载进度。

组件发出操作回调：

- 访问 URL。
- 后退。
- 前进。
- 刷新。
- 停止加载。
- 打开浏览历史。
- 面板展开状态变化。
- 通用动作点击事件。

## 非功能需求

- 不新增 `SYSTEM_ALERT_WINDOW` 等悬浮窗权限。
- 不新增第三方依赖。
- 不使用 Compose `AndroidView` 承载真实网页。
- 组件必须能直接添加到 `FrameLayout` 根布局，位于 WebView 上层。
- UI 操作必须在主线程执行。
- 触控目标尽量不小于 56dp，悬浮球主触控目标不小于 72dp。
- 面板不能遮挡后无法关闭，关闭按钮始终可见。
- 组件不得改变现有返回键顺序。后续接入时仍保持：WebView 历史优先，子 WebView 栈其次，最后才是家长验证或关闭。
- 组件不直接读取跨进程 `SharedPreferences`。正常模式是否启用应由宿主通过明确运行时状态决定。
- 组件内部只做 UI 状态和事件分发，不绕过宿主安全策略。
- 动作模型必须可扩展，后续新增能力不应复制拖拽吸附逻辑。

## 下一版实现规格

下一版从“浏览器控制悬浮面板”升级为“悬浮球操作入口”：

1. 保留 `FloatingBrowserControlsOverlay` 作为对外入口，避免后续接入代码大幅迁移。
2. 新增通用数据模型：
   - `FloatingControlAction`
   - `FloatingControlSection`
   - `FloatingControlActionStyle`
3. 浏览器状态更新时生成默认浏览器分组，而不是把按钮固定写死在面板结构中。
4. 新增 `setExtraSections(sections)` API，允许宿主注入后续功能分组。
5. 新增 `onActionSelected(actionId)` 回调，所有通用动作和固定面板动作通过稳定 id 上报。
6. 面板内动作区改为可滚动分组行，保证窄屏不裁切。
7. 面板头部固定保留关闭按钮，避免动作分组过多时关闭入口被滚动内容遮挡。
8. 继续保持 URL 输入区作为浏览器分组的专用内容；未来如果有非浏览器主分组，再按 section type 拆分。
9. 保留 72dp 悬浮球触控目标、边缘半隐藏和横竖屏重新约束。

本版本完成后，正常模式接入只需要决定：

- 是否显示该悬浮入口。
- 当前 WebView 状态如何映射到 `FloatingBrowserControlsState`。
- 通用动作 id 如何映射到宿主能力。

## 后续正常模式接入计划

后续多模式切换完成后，在正常模式接入该组件：

1. 在 `WebViewActivity` 创建 root `FrameLayout` 后，按运行时模式判断是否添加悬浮球。
2. 在 `WebViewClient` / `WebChromeClient` 回调中调用 `updateState` 同步 URL、标题、进度和前进后退能力。
3. 将组件回调接到当前顶层 WebView：
   - `onNavigateToUrl` -> `currentWebView.loadUrl(url)`。
   - `onBack` -> `handleNativeBack()` 或当前 WebView `goBack()`。
   - `onForward` -> `currentWebView.goForward()`。
   - `onRefresh` -> `currentWebView.reload()`。
   - `onStopLoading` -> `currentWebView.stopLoading()`。
4. 子窗口 WebView 入栈或销毁时更新当前状态。
5. 视频全屏、家长验证弹窗、超时弹窗显示期间隐藏或禁用悬浮面板。
6. 如需保存悬浮球位置，通过宿主持久化；不要让 `:webview` 进程依赖主进程偏好立即刷新。

## 验收标准

- `:app:compileDebugKotlin` 通过。
- 新组件不引入新权限和新依赖。
- 悬浮球可拖拽，松手吸附左右边缘。
- 空闲后可半隐藏，半隐藏状态仍可点击恢复。
- 面板可展开、收起，URL 输入和浏览按钮通过回调输出。
- 组件可独立添加到 `FrameLayout`，不影响现有 WebView 全屏承载路径。
